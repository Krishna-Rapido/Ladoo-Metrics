3. API Endpoints (added to main.py)

# Causal Inference Lab — 8 endpoints
POST /causal/psm
Run propensity score matching. Returns: overlap data, balance metrics,
matched ATT, naive vs matched comparison, narrative.
POST /causal/impact
Run CausalImpact analysis. Returns: counterfactual time series,
pointwise impact, cumulative impact, summary stats, narrative.
POST /causal/hte
Run heterogeneous treatment effect analysis. Returns: CATE by segment,
feature importance, CATE distribution, individual CATEs, narrative.
POST /causal/synthetic-control
Run synthetic control. Returns: actual vs synthetic series,
donor weights, gap estimates, placebo test results, narrative.
POST /causal/rdd
Run regression discontinuity. Returns: RD estimate, scatter data,
McCrary density test, bandwidth sensitivity, narrative.
POST /causal/recommend
Auto-recommend which method(s) to use based on experiment data.
Checks: has control group? has city column? has running variable?
POST /causal/validate
Pre-flight validation: checks data sufficiency, overlap, sample sizes.
Returns warnings and feasibility score per method.
POST /causal/export
Export full causal analysis as report item (chart data + narrative).
Integrates with existing ReportContext.

4. Data Preparation Pipeline (inside causal_inference.py)

How Session Data Gets Transformed for Each Method
Input: Session DataFrame (captain_id × yyyymmdd × cohort × metrics)
+ pre_start, pre_end, post_start, post_end dates from user config
+ outcome_metric (which metric to measure treatment effect on)
prepare_for_psm(df, config)
1. Filter to pre-period dates
2. Aggregate per captain: mean, std, trend_slope, active_days for each metric
3. Create feature matrix X (pre-period covariates)
4. Create treatment vector T (1=test, 0=control)
5. Compute post-period outcome Y per captain
→ Returns: X, T, Y, captain_ids
prepare_for_causal_impact(df, config)
1. Aggregate to daily time series (date → mean/sum of outcome)
2. If control exists: create control series as covariate
3. Format as DatetimeIndex pandas Series
4. Define pre/post period tuples
→ Returns: y_series, [x_covariates], pre_period, post_period
prepare_for_hte(df, config)
1. Same as PSM: create X (pre-period features), T, Y
2. Additional: extract segment columns for waterfall grouping
3. CausalForestDML needs: Y, T, X, W (optional instruments)
→ Returns: Y, T, X, segment_cols, captain_ids
prepare_for_synth_control(df, config)
1. Require "city" column in data
2. Aggregate: city × date → outcome metric
3. Pivot to wide format: rows=dates, cols=cities
4. User selects treated city
→ Returns: panel_df, treated_city, donor_cities, intervention_date
prepare_for_rdd(df, config)
1. User selects: running_variable column, cutoff_value, outcome_metric
2. Aggregate per captain: mean of running variable (if multiple dates)
3. Aggregate per captain: post-period mean of outcome
→ Returns: running_var_array, outcome_array, cutoff_value

Step 2

+ auto-generated narrative at bottom

7. Auto-Narrative Engine (What Makes It "Explainable")

Every method generates a structured narrative
Option A: Template-based (fast, deterministic)
Pre-written templates with variable slots:

"After matching on {n_covariates} covariates, the treatment effect is {att}% (95% CI: [{ci_low}%, {ci_high}%]). {bias_sentence}"

✓ Fast, no API call
✓ Consistent output
✗ Less nuanced interpretation
Option B: LLM-enhanced (richer, contextual)
Feed results to Claude/GPT for natural interpretation:

"Given these PSM results for a captain incentive experiment, write a 3-paragraph interpretation..."

✓ Contextual, domain-aware
✓ Suggests next steps
✗ +2-3s latency, API cost
Recommendation: Both. Template-based renders instantly with results. "Explain Further" button triggers LLM narrative (reusing NarrativeExplainer pattern).
